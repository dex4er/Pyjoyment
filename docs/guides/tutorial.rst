Tutorial
========

Get started with Pyjoyment.

A quick example-driven introduction to the wonders of :mod:`Pyjoyment.Lite`.
Almost everything you'll learn here also applies to full :mod:`Pyjoyment`
applications.

This is only the first of the guides. Other guides delve deeper into topics
like :doc:`growing <growing>` a :mod:`Pyjoyment.Lite` prototype into a
well-structured :mod:`Pyjoyment` application, :doc:`routing <routing>`,
:doc:`rendering <rendering>` and more, in the guides of Mojolicious
until Pyjoyment has its own. It is highly encouraged that readers continue on
to the remaining guides after reading this one.

Commands
--------

Many different commands of :mod:`Pyjoyment.Commands` are automatically
available from the command line. CGI, WSGI and ASGI environments can even be
detected and will usually just work without commands.

.. code-block:: console

    $ ./myapp.py daemon
    Web application available at http://127.0.0.1:3000

    $ ./myapp.py daemon -l http://*:8080
    Web application available at http://127.0.0.1:8080

    $ ./myapp.py cgi
    ...CGI output...

    $ ./myapp.py get /
    Hello World!

    $ ./myapp.py
    ...List of available commands (or automatically detected environment)...

A call to :meth:`~Pyjoyment.Pyjoyment_App.start` (``app.start()``), which
starts the command system, should be the last expression in your
application, because its return value can be significant.

.. code-block:: python

    # Use sys.argv to pick a command
    app.start()

    # Start the "daemon" command
    app.start('daemon', '-l', 'http://*:8080')

Reloading
---------

Your application will automatically reload itself if you start it with the
:mod:`Pyjo.Server.Reload` development web server, so you don't have to
restart the server after every change.

.. code-block:: console

    $ pyjo-reload ./myapp.py
    Web application available at http://127.0.0.1:3000

For more information about how to deploy your application see also
`the deployment in the cookbook
<https://docs.mojolicious.org/Mojolicious/Guides/Cookbook#DEPLOYMENT>`_.

Routes
------

Routes are basically just fancy paths that can contain different kinds of
placeholders and usually lead to an action, if they match the path part of
the request URL. The first argument passed to all actions (``c``) is a
:mod:`Pyjoyment.Controller` object, containing both the HTTP request and
response. A route is a decorator of its action, which returns the route.

.. literalinclude:: tutorial/routes.py
    :language: python

Response content is often generated by actions with
:meth:`~Pyjoyment.Controller.Pyjoyment_Controller.render`, but more about that
later.

Stash and templates
-------------------

The :meth:`~Pyjoyment.Controller.Pyjoyment_Controller.stash` is used to pass
data to templates, which can be inlined in the ``DATA`` section, the
docstring of the script after a line ``__DATA__``. A few stash values like
``template``, ``text`` and ``data`` are reserved and will be used by
:meth:`~Pyjoyment.Controller.Pyjoyment_Controller.render` to decide how a
response should be generated.

.. literalinclude:: tutorial/stash.py
    :language: python

The code of a template is Python, and the values of the stash are its
variables. For more information about templates see also
:mod:`Pyjo.Template`.

JSON
----

JSON is the most commonly used data-interchange format for web services.
:mod:`Pyjoyment` loves JSON and comes with :mod:`Pyjo.JSON` built right in,
which is accessible through :meth:`~Pyjo.Message.Pyjo_Message.json` as well as
the reserved stash value ``json``.

.. literalinclude:: tutorial/json_reverse.py
    :language: python

You can send JSON documents from the command line with
:mod:`Pyjoyment.Command.get`.

.. code-block:: console

    $ ./myapp.py get -M PUT -c '{"message":"Hello Pyjo!"}' /reverse

Built-in ``exception`` and ``not_found`` pages
----------------------------------------------

During development you will encounter these pages whenever you make a
mistake, they are gorgeous and contain a lot of valuable information that will
aid you in debugging your application.

.. literalinclude:: tutorial/exception_pages.py
    :language: python

You can even use CSS selectors with :mod:`Pyjoyment.Command.get` to extract
only the information you're actually interested in.

.. code-block:: console

    $ ./myapp.py get /dies '#error'

And don't worry about revealing too much information on these pages, they are
only available during development, and will be replaced automatically with
pages that don't reveal any sensitive information in a production
environment.

Route names
-----------

All routes can have a name associated with them, this allows automatic
template detection and backreferencing with
:meth:`~Pyjoyment.Controller.Pyjoyment_Controller.url_for`, on which many
methods and helpers like ``link_to`` of
:mod:`Pyjoyment.Plugin.TagHelpers` rely.

.. literalinclude:: tutorial/route_names.py
    :language: python

Nameless routes get an automatically generated one assigned that is simply
equal to the route itself without non-word characters.

Layouts
-------

Templates can have layouts too, you just select one with the helper
``layout`` of :mod:`Pyjoyment.Plugin.DefaultHelpers` and place the result of
the current template with the helper ``content``.

.. literalinclude:: tutorial/layouts.py
    :language: python

The stash or helpers like ``title`` can be used to pass additional data to the
layout. A value of the stash hides the helper of its name in a template, as
Python has one namespace for both, so the layout calls the helper ``title``,
which keeps its value in the stash, as a method of ``c``.

Plugins
-------

Plugins are application extensions that help with code sharing and
organization. You can load a plugin with the function ``plugin`` of
:mod:`Pyjoyment.Lite`, which can omit the ``Pyjoyment.Plugin.`` part of the
name, and optionally provide configuration for the plugin.

.. literalinclude:: tutorial/plugins.py
    :language: python

:mod:`Pyjoyment.Plugin.Config` is a built-in plugin which can populate
:meth:`~Pyjo.App.Pyjo_App.config` using a config file. Plugins can also set
up routes, hooks, handlers, or even load other plugins. A list of built-in
plugins can be found at :mod:`Pyjoyment.Plugins`.

Placeholders
------------

Route placeholders allow capturing parts of a request path until a ``/`` or
``.`` separator occurs, similar to the regular expression ``([^/.]+)``.
Results are accessible via
:meth:`~Pyjoyment.Controller.Pyjoyment_Controller.stash` and
:meth:`~Pyjoyment.Controller.Pyjoyment_Controller.param`.

.. literalinclude:: tutorial/placeholders.py
    :language: python

To separate them from the surrounding text, you can surround your
placeholders with ``<`` and ``>``, which also makes the colon prefix
optional.

Static files
------------

Similar to templates, but with only a single file extension and optional
Base64 encoding, static files can be inlined in the ``DATA`` section and are
served automatically.

.. literalinclude:: tutorial/static_files.py
    :language: python

External static files are not limited to a single file extension and will be
served automatically from a ``public`` directory if it exists.

.. code-block:: console

    $ mkdir public
    $ mv something.js public/something.js
    $ mv pyjoyment.tar.gz public/pyjoyment.tar.gz

Both have a higher precedence than routes for ``GET`` and ``HEAD`` requests.
Content negotiation with ``Range``, ``If-None-Match`` and
``If-Modified-Since`` headers is supported as well and can be tested very
easily with :mod:`Pyjoyment.Command.get`.

.. code-block:: console

    $ ./myapp.py get /something.js -v -H 'Range: bytes=2-4'

Home
----

You can use :attr:`~Pyjo.App.Pyjo_App.home` to interact with the directory
your application considers its home. This is the directory it will search for
``public`` and ``templates`` directories, but you can use it to store all
sorts of application specific data.

.. code-block:: console

    $ mkdir cache
    $ echo 'Hello World!' > cache/hello.txt

There are many useful methods :mod:`Pyjo.Home` inherits from
:mod:`Pyjo.File`, like :meth:`~Pyjo.File.Pyjo_File.child` and
:meth:`~Pyjo.File.Pyjo_File.slurp`, that will help you keep your application
portable across many different operating systems.

.. literalinclude:: tutorial/home.py
    :language: python

You can also introspect your application from the command line with
:mod:`Pyjoyment.Command.eval`.

.. code-block:: console

    $ ./myapp.py eval -v 'app.home'

Sessions
--------

Cookie-based sessions just work out of the box, as soon as you start using
them through the helper ``session`` of :mod:`Pyjoyment.Plugin.DefaultHelpers`.
Just be aware that all session data gets serialized with :mod:`Pyjo.JSON` and
stored client-side, with a cryptographic signature to prevent tampering.

.. literalinclude:: tutorial/sessions.py
    :language: python

Note that you should use custom :attr:`~Pyjoyment.Pyjoyment_App.secrets` to
make signed cookies really tamper resistant.

.. code-block:: python

    app.secrets = ['My secret passphrase here']

File uploads
------------

All files uploaded via ``multipart/form-data`` request are automatically
available as :mod:`Pyjo.Upload` objects from
:meth:`~Pyjoyment.Controller.Pyjoyment_Controller.param`. And you don't have to
worry about memory usage, because all files above 250KiB will be
automatically streamed into a temporary file. To build HTML forms more
efficiently, you can also use tag helpers like ``form_for`` of
:mod:`Pyjoyment.Plugin.TagHelpers`, whose attributes follow its block.

.. literalinclude:: tutorial/file_uploads.py
    :language: python

To protect you from excessively large files there is also a limit of 16MiB by
default, which you can tweak with the attribute
:attr:`~Pyjoyment.Pyjoyment_App.max_request_size`.

.. code-block:: python

    # Increase limit to 1GiB
    app.max_request_size = 1073741824

User agent
----------

With :mod:`Pyjo.UserAgent`, which is available through the helper ``ua`` of
:mod:`Pyjoyment.Plugin.DefaultHelpers`, there's a full featured HTTP and
WebSocket user agent built right in. Especially in combination with
:mod:`Pyjo.JSON` and :mod:`Pyjo.DOM` this can be a very powerful tool.

.. literalinclude:: tutorial/user_agent.py
    :language: python

An action is an ``async`` function too, which can ``await`` a promise of the
user agent. A blocking request, without a callback, does not work in an
action of a server that runs on the asyncio event loop, which does not run
inside itself; it is for scripts and tests. For more information about the
user agent see also
`the user agent in the cookbook
<https://docs.mojolicious.org/Mojolicious/Guides/Cookbook#USER-AGENT>`_.

Mode
----

You can use the :mod:`Pyjo.Log` object from :attr:`~Pyjo.App.Pyjo_App.log` to
portably collect debug messages and automatically disable them later in a
production setup by changing the :mod:`Pyjoyment` operating mode, which can
also be retrieved from the attribute :attr:`~Pyjoyment.Pyjoyment_App.mode`.

.. literalinclude:: tutorial/mode.py
    :language: python

The default operating mode will usually be ``development`` and can be changed
with command line options or the ``PYJO_MODE`` environment variable. A mode
other than ``development`` will raise the log level from ``trace`` to
``info``. All messages will be written to ``sys.stderr`` by default.

.. code-block:: console

    $ ./myapp.py daemon -m production

Mode changes also affect a few other aspects of the framework, such as the
built-in ``exception`` and ``not_found`` pages. Once you switch modes from
``development`` to ``production``, no sensitive information will be revealed
on those pages anymore.

Testing
-------

Testing your application is as easy as creating a ``t`` directory and filling
it with normal Python tests like ``t/basic.py``, which can be a lot of fun
thanks to :mod:`Pyjo.Test.Pyjo`.

.. code-block:: python

    from Pyjo.Test import *

    import Pyjo.File
    import Pyjo.Test.Pyjo

    import re

    # Portably point to "../myapp.py"
    script = Pyjo.File.curfile().dirname().sibling('myapp.py')

    t = Pyjo.Test.Pyjo.new(script)
    t.get_ok('/').status_is(200).content_like(re.compile(r'Funky'))

    done_testing()

Just run your tests with :mod:`Pyjo.Prove`.

.. code-block:: console

    $ pyjo-prove -l -v
    $ pyjo-prove -l -v t/basic.py
